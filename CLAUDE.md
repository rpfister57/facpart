# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working
with code in this repository.

## Project Overview

`facpart` is an installable R package providing tools for partitioning
2-dimensional point configurations (such as multidimensional-scaling
output) according to Facet Theory. It implements three partition types —
axial (parallel lines), radial (nested circles or ellipses), and angular
(wedge sectors) — plus ellipse-fitting utilities.

The git repository is rooted here at `facpart/`. This is a standalone
package; there is no dependency on any script files outside this
directory.

## Development Workflow

All development commands run from inside the `facpart/` directory (or
with the `facpart.Rproj` open in RStudio):

``` r

devtools::load_all()   # load all functions without installing (fastest for interactive dev)
devtools::document()   # regenerate man/ and NAMESPACE from roxygen2 comments
devtools::install()    # install locally
devtools::check()      # run R CMD check
devtools::build()      # build the source tarball (facpart_x.y.z.tar.gz)
```

Do not edit `NAMESPACE` by hand — it is auto-generated by roxygen2.

`.Rprofile` loads `devtools` in interactive sessions, so the commands
above work unprefixed in RStudio. In non-interactive use call them as
`Rscript -e 'devtools::document()'`.

Run the test suite with:

``` r

devtools::test()                                          # all tests
testthat::test_file("tests/testthat/test-guttman.R")     # single file
```

Currently only `guttman.R` functions have formal tests
(`tests/testthat/test-guttman.R`). Ad-hoc testing for other functions is
done interactively via `devtools::load_all()` followed by manual calls.

## Shared Partition Contract

Every partition function has the same skeleton: **validate → optimise
geometry → assign regions → map regions to groups → draw → return**. The
last three steps are identical across
[`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md),
`radialCircle(s)()`, `radialEllipse(s)()` and
[`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md),
so a change in one usually belongs in all of them:

1.  `sector` — integer vector, one entry per input point **in original
    row order**, giving the region the point fell into.
2.  `count_mat[g, r]` — group × region count table, built with
    `tabulate(..., nbins = k)`.
3.  `.assign_groups(count_mat)` (`utils.R`) — brute-force over all `k!`
    bijections, returning the region → group index mapping that
    maximises correct classifications.
    `majority <- levels(group)[assignment]`, so `majority[r]` is the
    group label owning region `r`. **Regions are matched to groups
    optimally, not by factor-level order**, which is why `misclass` can
    be lower than a naive level-order reading suggests.
4.  `misclass_idx <- which(<point label> != majority[sector])`, and
    `misclass_points` is always a data frame with columns `x`, `y`,
    `label` — this is the contract
    [`highlightMisclass()`](https://rpfister57.github.io/facpart/reference/highlightMisclass.md)
    consumes (it also accepts the whole result list).

Result-list shape by function:

| Function | Geometry fields | `misclass` type | `sector`/`majority` |
|----|----|----|----|
| [`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md) | `slope`, `intercept` | integer | no — returns `predicted` instead |
| [`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md) | `slope`, `intercepts`, `angle`, `margin` | integer | yes |
| [`radialCircle()`](https://rpfister57.github.io/facpart/reference/radialCircle.md) | `center`, `radius` | integer | yes |
| [`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md) | `cx`, `cy`, `radii` | integer | yes |
| [`radialEllipse()`](https://rpfister57.github.io/facpart/reference/radialEllipse.md) | `cx`, `cy`, `a`, `b`, `angle` | list `(n, indices)` | yes |
| [`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md) | `cx`, `cy`, `a`, `b`, `angle` (vectors) | list `(n, indices)` | yes |
| [`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md) | `cuts`, `margin`, `center`, `pt_angles` | integer | yes |

All of them also return `misclass_points`.
[`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md)
is the odd one out: it is a pure LDA classifier, so it has no
region/group matching step and reports `predicted` (the LDA class
factor) instead of `sector`/`majority`.

All partition functions —
[`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md),
[`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md),
[`radialCircle()`](https://rpfister57.github.io/facpart/reference/radialCircle.md),
[`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md),
[`radialEllipse()`](https://rpfister57.github.io/facpart/reference/radialEllipse.md),
[`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md),
[`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md)
— plus
[`ellipseInConfig()`](https://rpfister57.github.io/facpart/reference/ellipseInConfig.md)
take a `fill` argument; all except
[`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md)/[`ellipseInConfig()`](https://rpfister57.github.io/facpart/reference/ellipseInConfig.md)
(fixed 2-colour `cols`) additionally take `cols` (auto-generated from
[`grDevices::hcl.colors()`](https://rdrr.io/r/grDevices/palettes.html)
when `NULL`, alpha-blended via
[`adjustcolor()`](https://rdrr.io/r/grDevices/adjustcolor.html)).

Fill geometry differs per family: radial functions use
[`polypath()`](https://rdrr.io/r/graphics/polypath.html) with an
even-odd rule to shade rings between nested boundaries,
[`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md)
clips the plot rectangle (`par("usr")`) strip by strip with
`.clip_halfplane()` — a Sutherland-Hodgman half-plane clipper in
`axial.R` that keeps the shading correct for steep and vertical
separators (do not replace it with slope/intercept polygon arithmetic) —
and
[`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md)
draws each wedge as a
[`polygon()`](https://rdrr.io/r/graphics/polygon.html) pie slice from
the center out to `2 * plot diagonal`, relying on R’s default
plot-region clipping (`par("xpd") = FALSE`) rather than manual rectangle
clipping.

### Input-validation inconsistency

[`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md)
**requires** `group` to already be a factor
(`if (!is.factor(group)) stop(...)`); the axial and radial functions
coerce with
[`as.factor()`](https://rdrr.io/r/base/factor.html)/[`factor()`](https://rdrr.io/r/base/factor.html).

## Internal Dependencies

`radial-ellipse.R` calls `.best_radius()` which is defined in
`radial-circle.R`. This cross-file dependency exists in two places: the
independent-center ellipse path (nesting constraint) and the fixed-shape
[`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md)
path (scale-factor scan). When loading the package this is invisible,
but if sourcing files interactively, source `radial-circle.R` first.

Private helpers use a `.` prefix (e.g., `.circle_pts`, `.in_ellipse`,
`.arc_mid`) and are tagged `#' @noRd`. They are internal to their file,
except `.best_radius()` (above) and the `utils.R` helpers.

Three `utils.R` helpers currently have **no callers**: `.permutations()`
(superseded by
[`gtools::permutations()`](https://rdrr.io/pkg/gtools/man/combinations.html)
inside `.assign_groups()`), `.d2r()` and `.r2d()`. Don’t spend time
hunting for their call sites; they are kept as available utilities.

## Key Algorithms

### Ellipse types (`ellipse.R`)

- **`"maxdist"`** (default): covariance-based ellipse centered at the
  data centroid, scaled to the maximum Mahalanobis distance + 5% buffer.
- **`"bestfit"`**: minimises sum of squared normalised elliptic
  distances via BFGS; initial guess from covariance ellipse.
- **`"minbound"`**: exact minimax minimum-area enclosing ellipse via
  `ellipsoidhull()`.

[`ellipseInConfig()`](https://rpfister57.github.io/facpart/reference/ellipseInConfig.md)
supports `mid = "centroid"` (default) or `mid = "nullnull"` (forces
center at origin). The `angle` in all ellipse output is in **radians**.

### Axial partitions (`axial.R`)

- **[`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md)**:
  binary split. Classical LDA Bayes-rule boundary — perpendicular to LD1
  through the midpoint of class means. Requires exactly 2 group levels.
  Vertical-line guard: when `|w[2]| < 1e-10`, `slope = Inf` and
  `intercept` carries the x-position. Returns `predicted` (LDA class
  factor); the only function that does.
- **[`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md)**:
  k ≥ 2 groups, k−1 parallel lines. Joint search over **angle and
  cuts**: grid of `n_angles` angles in \[0, π) plus LDA’s LD1 direction;
  for each angle, exhaustive enumeration of C(n−1, k−1) cut placements.
  Ties broken by **largest minimum margin** (perpendicular distance from
  a cut line to the nearest point). Same vertical-line guard as
  [`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md).
  The cut search is **vectorised via cumulative per-group counts**
  (`cum[i+1, g]` = count of group g among the first i sorted points): a
  segment’s group counts are a vector subtraction
  `cum[hi+1,] - cum[lo+1,]`, and all C(n−1, k−1) candidate partitions
  are scored together with `pmax`/`pmin` — no per-combo R loop, no
  per-segment [`tabulate()`](https://rdrr.io/r/base/tabulate.html). This
  is ~17–23× faster than the previous per-combo loop for k ≥ 3 while
  returning bit-identical results (same enumeration and tie-break,
  `which.max` keeps the first-in-scan-order winner). Do not “simplify”
  this back to a nested loop over
  [`combn()`](https://rdrr.io/r/utils/combn.html) columns.
- **When to use which**: use
  [`axialLine()`](https://rpfister57.github.io/facpart/reference/axialLine.md)
  for the classical LDA classifier (optimal under Gaussian
  equal-covariance classes); use
  [`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md)
  for the empirically best parallel-line separator (can find a non-LD1
  direction that beats LDA on the training sample).

### Radial / nested circles (`radial-circle.R`)

- **[`radialCircle()`](https://rpfister57.github.io/facpart/reference/radialCircle.md)**
  /
  **[`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md)**:
  nested (inclusive) circles. Center optimised by **multi-start
  Nelder-Mead with `parscale`** set to the data range. Starts include
  the overall centroid, each group’s centroid, and (for
  [`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md))
  the previous circle’s center. Nesting constraint
  `r_s ≥ dist(center_s, center_{s−1}) + r_{s−1}` enforced via minimum
  radius during a brute-force radius scan (`.best_radius()`). `misclass`
  is a plain **integer**. Supplying both `cx, cy` to
  [`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md)
  makes all circles **concentric**.

### Radial / nested ellipses (`radial-ellipse.R`)

- **[`radialEllipse()`](https://rpfister57.github.io/facpart/reference/radialEllipse.md)**
  /
  **[`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md)**:
  elliptic analogue of the radial circle functions. Each ellipse has 5
  parameters `(cx, cy, a, b, angle)` optimised by Nelder-Mead with
  `parscale = c(x_range, y_range, max_range, max_range, pi)`.
  Multi-start includes the covariance ellipse of the inner groups plus
  an inflated copy of the previous ellipse. `misclass` is a **list
  `(n, indices)`** — count plus row indices. Angles are in radians
  internally; converted to degrees only for `draw.ellipse()`. When
  `ellipse` (a 5-vector) is supplied to
  [`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md),
  outer ellipses are uniform scalings sharing the fixed
  center/orientation/ratio; scale factors found by exact 1D scan via
  `.best_radius()`.
- **`misclass` type differs from circle functions**:
  [`radialEllipse()`](https://rpfister57.github.io/facpart/reference/radialEllipse.md)
  /
  [`radialEllipses()`](https://rpfister57.github.io/facpart/reference/radialEllipses.md)
  return `misclass` as a list `list(n, indices)`;
  [`radialCircle()`](https://rpfister57.github.io/facpart/reference/radialCircle.md)
  /
  [`radialCircles()`](https://rpfister57.github.io/facpart/reference/radialCircles.md)
  return `misclass` as a plain integer.

### Guttman monotonicity coefficient (`guttman.R`)

- **[`mu2()`](https://rpfister57.github.io/facpart/reference/mu2.md)**:
  Guttman’s mu2 for two vectors. Computed as
  `sum(dx * dy) / sum(|dx| * |dy|)` over all pairs (i, j), where
  `dx = x_i - x_j`. Returns values in \[−1, 1\]; `NaN` when all
  differences are zero. Uses pairwise NA deletion.
- **[`mu2df()`](https://rpfister57.github.io/facpart/reference/mu2df.md)**:
  Applies
  [`mu2()`](https://rpfister57.github.io/facpart/reference/mu2.md) to
  all column pairs of a data frame. Returns a full symmetric matrix
  (`as_dist = FALSE`, default) or a `dist` object of `sqrt(1 − mu2)`
  values (`as_dist = TRUE`). Unlike the partition functions, these have
  no plot side-effect.

### Angular partition (`angular.R`)

- **[`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md)**:
  k wedge sectors from a common center. Brute-force over
  `M = choose(n, k)` candidate cut-gap k-tuples (`combn(n, k)`);
  tie-broken by **largest minimum 2D distance** from any cut ray to the
  nearest point. The score of a candidate is the exact
  **bijection-constrained** misclassification (best total correct over
  all `k!` arc-to-group assignments, each group used exactly once — the
  same criterion `.assign_groups()` applies downstream).
  `.angular_search()` computes every per-candidate quantity as a
  length-`M` vector indexed out of the cumulative count table, so loops
  run over `k`/`k!`, never over candidates — the same vectorisation
  pattern as
  [`axialLines()`](https://rpfister57.github.io/facpart/reference/axialLines.md)
  (loop the small fixed dimension, vectorise the candidate axis).

  Scoring is **bound-and-prune** in two stages, because the `k!` scan is
  the expensive part:

  1.  *All M, cheap*: `ub`, the **unconstrained** best-correct — each
      arc independently keeps its local-majority group. Any bijection is
      one particular per-arc group choice, so `exact <= ub` always,
      making it a valid upper bound. Costs `k * (2k - 1)` vector ops vs
      `k! * (k + 1)` for the exact scan, and needs no `M x k` matrix.
  2.  *Tiny subset, exact*: only candidates whose `ub` is high enough to
      still win get the full `k!` scan; the threshold walks down until
      some candidate’s exact score reaches it, at which point every
      unscanned candidate has `ub < best` and is provably excluded.

  The bound is tight in practice (typically a *handful* of the `M`
  candidates survive — e.g. 8 of 487,635 at n=60/k=4), which is what
  makes this fast. The margin tie-break is likewise computed **only for
  the co-minimal candidates**, not all `M`. Degenerate inputs (all one
  group, alternating labels) loosen the bound but do not blow up — worst
  case degrades toward the full scan.

  **Do not “simplify” this back to scoring all `M` candidates exactly,
  and do not drop the bijection constraint in favour of per-arc local
  majorities** — the latter was a real bug (search minimised a different
  quantity than the reported `misclass`; see git history), the former
  was a ~3x slowdown. Any change here must be checked for
  *bit-identical*
  `misclass`/`margin`/`cuts`/`center`/`sector`/`majority` against the
  previous implementation, not just equal `misclass`.

  Center is **optimised** when either `cx` or `cy` is `NULL` (default);
  starts are the overall centroid, the bounding-box corners, plus each
  group’s centroid. Ray length is computed from `par("usr")`. When
  `fill = TRUE`, each of the `k` wedges is shaded as a
  [`polygon()`](https://rdrr.io/r/graphics/polygon.html) pie slice
  (center plus a 100-point arc at that ray length); relies on default
  plot-region clipping rather than the rectangle-clipping used
  elsewhere, since a pie slice is already bounded. `angularPartition3()`
  (fixed k=3 reference) exists only in the companion script layer and is
  not part of this package.

- All exported drawing functions accept `add = TRUE` (default, draw on
  the existing plot) or `add = FALSE` (call
  [`plot()`](https://rdrr.io/r/graphics/plot.default.html) first).
  [`ellipseInConfig()`](https://rpfister57.github.io/facpart/reference/ellipseInConfig.md)
  labels no points when `add = FALSE`; all other functions also draw
  group labels via
  [`graphics::text()`](https://rdrr.io/r/graphics/text.html).

#### `angularPartition()` runtime

Measured on macOS / single-threaded R with the current implementation,
free center (the default), on clustered data with moderate group
overlap. Order-of-magnitude only — see the caveats.

| n  k   | k=2     | k=3     | k=4     | k=5         | k=6        |
|--------|---------|---------|---------|-------------|------------|
| **10** | \<0.01s | \<0.01s | \<0.01s | 0.005–0.02s | 0.02–0.06s |
| **20** | \<0.01s | \<0.01s | ~0.005s | 0.02–0.14s  | 0.07–0.9s  |
| **30** | \<0.01s | \<0.01s | ~0.02s  | 0.8–1.6s    | 0.8–9s     |
| **40** | \<0.01s | \<0.01s | ~0.07s  | 5–8s        | ~60s       |
| **50** | \<0.01s | ~0.01s  | ~0.17s  | 15–33s      | ~300s      |

Cost is driven by the candidate count `M = choose(n, k)`, roughly
`time ≈ (search calls) × M × k(2k−1) × const`:

| n  k   | k=2   | k=3    | k=4     | k=5       | k=6        |
|--------|-------|--------|---------|-----------|------------|
| **10** | 45    | 120    | 210     | 252       | 210        |
| **20** | 190   | 1,140  | 4,845   | 15,504    | 38,760     |
| **30** | 435   | 4,060  | 27,405  | 142,506   | 593,775    |
| **40** | 780   | 9,880  | 91,390  | 658,008   | 3,838,380  |
| **50** | 1,225 | 19,600 | 230,300 | 2,118,760 | 15,890,700 |

Caveats when interpreting these:

- **The ranges are real, not noise: the same `(n, k)` varies up to ~10x
  with the data.** The multi-start Nelder-Mead center search breaks out
  early (`if (best$value == 0) break`) as soon as a start reaches zero
  misclassification, so the number of `.angular_search()` calls swings
  between **4 and 95**. Well-separated facet structure → few calls,
  fast; heavily overlapping groups → all `3 + k` starts run, slow.
  Measured: n=30/k=6 was 0.77s (4 calls) on one dataset and 9.2s (60
  calls) on another.
- **Supplying `cx`/`cy` reduces this to exactly one search call**, which
  is the single biggest performance lever. n=50/k=6 drops from ~305s to
  ~8s — and ~4.7s of that remainder is just building the 364 MB
  `combn(50, 6)` matrix, not searching.
- **`k <= 4` is effectively free** for any n up to 50 (worst case
  0.17s). `k = 5` is the inflection point; `k = 6` at n \>= 40 costs
  minutes. Don’t optimise for `k <= 4` workloads.
- Benchmark scripts are not kept in the repo; regenerate by timing
  [`angularPartition()`](https://rpfister57.github.io/facpart/reference/angularPartition.md)
  over the grid if these need refreshing after a change.

## Coding Conventions

- Use `_` not `.` for object names (e.g., `grp_int`, not `grp.int`).
- Indentation: 4 spaces.
- Do not use ggplot2 for plots; all graphics use base R.
- Never use function names as object names (e.g., avoid
  `levels <- levels(x)`).
- Private helpers are prefixed with `.` and tagged `#' @noRd`.
- Do not add top-level
  [`require()`](https://rdrr.io/r/base/library.html) calls — package
  imports handle dependencies.
- Every exported function returns `invisible(NULL)` when
  `output = FALSE`; this is a package-wide convention.
- [`ellipseInConfig()`](https://rpfister57.github.io/facpart/reference/ellipseInConfig.md)
  has a `labs` parameter that is currently unused but kept for backward
  compatibility — do not remove it.

## pkgdown / GitHub Pages

The package site is deployed to `https://rpfister57.github.io/facpart/`
via the workflow at `.github/workflows/pkgdown.yaml`. It triggers on
push to `main`/`master`, on pull requests (build only, no deploy), on
published releases, and manually via `workflow_dispatch`.

The workflow runs
[`pkgdown::build_site_github_pages()`](https://pkgdown.r-lib.org/reference/build_site_github_pages.html)
(output goes to `docs/`) and then deploys `docs/` to the `gh-pages`
branch using `JamesIves/github-pages-deploy-action` with `clean: false`.
Configuration is in `_pkgdown.yml` (Bootstrap 5 template; URL matches
`DESCRIPTION`’s `URL:` field).

To rebuild the site locally:

``` r

pkgdown::build_site()
```

The `docs/` directory is excluded from the package tarball via
`.Rbuildignore`.

**Caveat — the FacetedPartitions article has no source in the repo.**
`docs/articles/FacetedPartitions.html`/`.md` and its figures are
committed, but there is no `vignettes/` directory and no `.Rmd`/`.qmd`
anywhere in the tree. `build_site_github_pages()` cleans `docs/` before
building, so a rebuild drops the article from `docs/`; only the
`clean: false` deploy keeps the already-published copy alive on
`gh-pages`. If the article needs editing, restore/author its `.Rmd`
under `vignettes/` first — do not hand-edit the generated HTML.
