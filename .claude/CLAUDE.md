# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`facpart` is an installable R package providing tools for partitioning 2-dimensional point configurations (such as multidimensional-scaling output) according to Facet Theory. It implements three partition types — axial (parallel lines), radial (nested circles or ellipses), and angular (wedge sectors) — plus ellipse-fitting utilities.

The git repository is rooted here at `facpart/`. This is a standalone package; there is no dependency on any script files outside this directory.

## Development Workflow

All development commands run from inside the `facpart/` directory (or with the `facpart.Rproj` open in RStudio):

```r
devtools::load_all()   # load all functions without installing (fastest for interactive dev)
devtools::document()   # regenerate man/ and NAMESPACE from roxygen2 comments
devtools::install()    # install locally
devtools::check()      # run R CMD check
devtools::build()      # build the source tarball (facpart_x.y.z.tar.gz)
```

Do not edit `NAMESPACE` by hand — it is auto-generated by roxygen2.

`.Rprofile` loads `devtools` in interactive sessions, so the commands above work unprefixed in RStudio. In non-interactive use call them as `Rscript -e 'devtools::document()'`.

Run the test suite with:

```r
devtools::test()                                          # all tests
testthat::test_file("tests/testthat/test-guttman.R")     # single file
```

Formal tests cover `guttman.R` (`tests/testthat/test-guttman.R` — two assertions), `radial-circle.R` (`tests/testthat/test-radial-circle.R`), `axial.R` (`tests/testthat/test-axial.R`) and the cross-cutting factor-level-order invariance of every partition function (`tests/testthat/test-order-invariance.R`). The partition test files are the model to follow for the other partition families: it defines a `with_null_dev()` helper that wraps each call in `pdf(NULL)` / `dev.off()` plus `plot.new()`/`plot.window()`, and an independent `bij_err()` reimplementation of the bijection-constrained error so assertions never route through the same package internals they are testing. Its core property tests are *self-consistency* (`misclass` equals the error the returned geometry actually achieves) and *optimality* (equals an exhaustive brute-force reference) — both catch objective/report mismatches that equal-`misclass` comparisons miss. Ad-hoc testing for the remaining functions is done interactively via `devtools::load_all()` followed by manual calls.

Testing a **partition** function is different from testing `mu2()`: they all draw, and several read `par("usr")`, so a headless `Rscript` invocation silently opens the default device and leaves a stray `Rplots.pdf` in the working directory. Wrap such calls in `pdf(NULL)` / `dev.off()` (or `withr::with_pdf`) and assert on the returned `misclass` / `sector` / geometry fields rather than on the plot.

## File Structure

`R/` is split one file per partition family (`axial.R`, `radial-circle.R`, `radial-ellipse.R`, `angular.R`) plus `ellipse.R`, `guttman.R`, `utils.R`, `data.R`, and `facpart-package.R` (package docs and all `@importFrom` directives — no code). `man/` is generated by `devtools::document()` and should not be edited directly.

## Dependencies

`gtools` is reached via `gtools::permutations()` and therefore has **no `@importFrom` directive** in `facpart-package.R`/`NAMESPACE` — that is intentional, do not "fix" it by adding one. `graphics::text()` (the group-label call in every drawing function) is likewise always `::`-qualified and deliberately absent from the `@importFrom graphics` line; the other `graphics`/`stats`/`utils` functions are imported and called bare.

## Exported API

See `NAMESPACE` for the export list. All partition and ellipse-drawing functions draw on the **currently active plot window**. Call `plot()` before any of these functions.

`inoutEllipse()`, `mu2()`, and `mu2df()` have no `output` parameter — they always return their value directly. `highlightMisclass()` has no `output` parameter either — it is pure side-effect and always returns `invisible(NULL)`. All other exported functions follow the `output = TRUE/FALSE` convention.

### Signature quirks worth knowing before editing

- `radialCircle()` / `radialCircles()` expose a **user-facing dot-prefixed argument** `.method = "Nelder-Mead"` (the only alternative accepted is `"SANN"`; anything else `stop()`s). It is passed to `optim()` for the center search and is ignored by `radialCircles()` when `cx`/`cy` are both supplied. The `.` prefix normally marks internals in this package — this is the one exception, don't rename it.
- **Only the circle functions and `angularPartition()` take `cx`/`cy`.** `radialEllipse()` has no way to fix the center; `radialEllipses()` can only fix it indirectly, by passing a complete `ellipse = c(cx, cy, a, b, angle)` 5-vector (which also fixes orientation and axis ratio).
- `axialLines()` takes `n_angles = 180L` — the size of the angle grid, and the main runtime knob for that function.
- `LazyData: true`, so `gutt91` and `guttman65mds` are usable by name after `library(facpart)`/`load_all()`; no `data()` call needed.

## Shared Partition Contract

Every partition function has the same skeleton: **validate → optimise geometry → assign regions → map regions to groups → draw → return**. The last three steps are identical across `axialLines()`, `radialCircle(s)()`, `radialEllipse(s)()` and `angularPartition()`, so a change in one usually belongs in all of them:

1. `sector` — integer vector, one entry per input point **in original row order**, giving the region the point fell into.
2. `count_mat[g, r]` — group × region count table, built with `tabulate(..., nbins = k)`.
3. `.assign_groups(count_mat)` (`utils.R`) — brute-force over all `k!` bijections, returning the region → group index mapping that maximises correct classifications. `majority <- levels(group)[assignment]`, so `majority[r]` is the group label owning region `r`. **Regions are matched to groups optimally, not by factor-level order**, which is why `misclass` can be lower than a naive level-order reading suggests.
4. `misclass_idx <- which(<point label> != majority[sector])`, and `misclass_points` is always a data frame with columns `x`, `y`, `label` — this is the contract `highlightMisclass()` consumes (it also accepts the whole result list).

Result-list shape by function:

| Function | Geometry fields | `misclass` type | `sector`/`majority` |
|---|---|---|---|
| `axialLine()` | `slope`, `intercept` | integer | no — returns `predicted` instead |
| `axialLines()` | `slope`, `intercepts`, `angle`, `margin` | integer | yes |
| `radialCircle()` | `center`, `radius` | integer | yes |
| `radialCircles()` | `cx`, `cy`, `radii` | integer | yes |
| `radialEllipse()` | `cx`, `cy`, `a`, `b`, `angle` | list `(n, indices)` | yes |
| `radialEllipses()` | `cx`, `cy`, `a`, `b`, `angle` (vectors) | list `(n, indices)` | yes |
| `angularPartition()` | `cuts`, `margin`, `center`, `pt_angles` | integer | yes |

All of them also return `misclass_points`. `axialLine()` is the odd one out: it is a pure LDA classifier, so it has no region/group matching step and reports `predicted` (the LDA class factor) instead of `sector`/`majority`.

### Region shading (`fill = TRUE`)

In all seven partition functions — `axialLine()`, `axialLines()`, `radialCircle()`, `radialCircles()`, `radialEllipse()`, `radialEllipses()`, `angularPartition()` — `fill` is a **logical** (`FALSE` by default) and the colours come from `cols`. The binary functions (`axialLine()`, `radialCircle()`, `radialEllipse()`) hard-default `cols = c("steelblue", "tomato")`; the k-way ones default `cols = NULL` and auto-generate from `grDevices::hcl.colors()`, alpha-blended via `adjustcolor()`.

**`ellipseInConfig()` is the exception**: its `fill` is a **colour** passed straight to `draw.ellipse(col = fill)`, defaulting to `NA` (no fill), and it has no `cols` argument at all. Don't assume `fill = TRUE` works there.

Fill geometry differs per family: radial functions use `polypath()` with an even-odd rule to shade rings between nested boundaries, `axialLines()` clips the plot rectangle (`par("usr")`) strip by strip with `.clip_halfplane()` — a Sutherland-Hodgman half-plane clipper in `axial.R` that keeps the shading correct for steep and vertical separators (do not replace it with slope/intercept polygon arithmetic) — and `angularPartition()` draws each wedge as a `polygon()` pie slice from the center out to `2 * plot diagonal`, relying on R's default plot-region clipping (`par("xpd") = FALSE`) rather than manual rectangle clipping.

### Group coercion

All partition functions coerce `group` themselves — `as.factor(group)` in the axial and radial files, `factor(group, exclude = NA)` in `angular.R` — so callers may pass a character vector. (Earlier versions of `angularPartition()` hard-stopped on a non-factor `group`; that check is gone, but every function still stops on `NA` in `crd` or `group`, on non-2-column `crd`, on `nrow(crd) != length(group)`, and on `< 2` group levels.)

## Internal Dependencies

`radial-ellipse.R` calls `.best_radius()` which is defined in `radial-circle.R`. This cross-file dependency exists in two places: the independent-center ellipse path (nesting constraint) and the fixed-shape `radialEllipses()` path (scale-factor scan). When loading the package this is invisible, but if sourcing files interactively, source `radial-circle.R` first.

Private helpers use a `.` prefix (e.g., `.circle_pts`, `.in_ellipse`, `.arc_mid`) and are tagged `#' @noRd`. They are internal to their file, except `.best_radius()` (above) and the `utils.R` helpers.

`.best_radius()` is now used **only** by the sequential/independent-centers path in `radial-circle.R` and by `radial-ellipse.R`; the concentric `radialCircles()` branch and all of `radialCircle()` go through `.radial_search()` instead. So a change to `.best_radius()` still reaches `radialEllipse(s)()` — check both files.

### Factor level order must never matter

**No exported function's result may depend on the factor level order of `group`** — not the geometry, not `misclass`, not `majority`. R's default levels are alphabetical, so any dependence means the answer changes when groups are merely renamed. `tests/testthat/test-order-invariance.R` pins this down by running every function under all `k!` level orders and comparing geometry, the induced partition (as sets of point indices), `misclass` and `majority`. Run it after touching any search or any tie-break.

Two mechanisms make it hold:

- **`.nesting_orders()` (`utils.R`)** supplies the candidate inside-to-outside group orderings that `radialCircles()` and `radialEllipses()` need for their *sequential* fits. Both **search** these candidates and keep whichever minimises the bijection-constrained misclassification they report. Candidate 1 is the data-derived order (groups by mean distance from the configuration centroid, ties by level **name**); the rest are the remaining permutations in canonical order, sorted by the tuple of level names they induce, never by level index. Callers take **strict** improvements, so candidate 1 wins ties. Above `max_perm = 120` (i.e. `k >= 6`) only the data-derived order is returned, `attr(, "exhaustive")` is `FALSE`, and the callers **warn**. `radialCircle()` and `radialEllipse()` don't need it — both already try both orientations (`.elliptic_cuts_2()` loops `which_inner in 1L:2L`), as does the exact concentric branch of `radialCircles()`, which enumerates cut placements and so never consults an ordering at all.
- **`.assign_groups(count_mat, lev)`** — the optional `lev` argument only affects **ties**. Several bijections can score equally, and taking the first in permutation order picks by *group index*, which is exactly the level order; `majority` then changed under relabelling even when the geometry did not. Given `lev`, the tie goes to the assignment whose region → name tuple is lexicographically smallest. **Pass `lev` at reporting call sites** (all six `majority <- ...` sites do) and **omit it in inner scoring loops** like `.partition_err()`, where only the tie-independent best value is used.

An earlier attempt warned when the level order disagreed with the data instead of fixing the fit. That was the wrong shape of solution — it pushed the work onto the caller — and has been removed; don't reintroduce a `.check_level_order()`.

**`.perms_k(k)` (`utils.R`)** memoises `gtools::permutations(k, k)` in the `.perm_cache` environment. This is a **hot path**, not a micro-optimisation: `gtools::permutations()` is recursive and rebuilds the matrix on every call, and `.assign_groups()` runs once per candidate radius inside the refinement × ordering-search loops. Profiling put that rebuild at ~79% of `radialCircles()` at k=5; caching took k=5/n=60 from 8.8s to 0.57s and the k=7 concentric fallback from 7.7s to 0.16s. Use `.perms_k()`, never `gtools::permutations()` directly, in anything reachable from a loop.

**`.bij_best()` (`utils.R`) is shared by `axial.R` and `radial-circle.R`** — it is the single implementation of the bijection-constrained candidate scoring plus its two-stage bound-and-prune. A change there affects `axialLines()`, `radialCircle()` and `radialCircles()` at once; run both `test-axial.R` and `test-radial-circle.R`. Callers pass `cum` plus `lo_idx`/`hi_idx` lists of row indices into it (scalar entries allowed where a bound is constant across candidates) and get back `max_correct` and `at`, the co-minimal candidate set, so each caller applies its own margin tie-break to that small pool rather than to all `M`. `.angular_search()` deliberately does **not** use it: its arc `k` wraps around 2π, so its per-arc count is `total[g] - cum[ia, g] + cum[ib, g]`, which does not fit the linear `lo`/`hi` scheme. Leave that duplication alone.

Four `utils.R` helpers currently have **no callers**: `.permutations()` (superseded by `gtools::permutations()` inside `.assign_groups()`), `.d2r()`, `.r2d()` and `.draw_angle_line()`. Don't spend time hunting for their call sites; they are kept as available utilities.

## Key Algorithms

### Ellipse types (`ellipse.R`)
- **`"maxdist"`** (default): covariance-based ellipse centered at the data centroid, scaled to the maximum Mahalanobis distance + 5% buffer.
- **`"bestfit"`**: minimises sum of squared normalised elliptic distances via BFGS; initial guess from covariance ellipse.
- **`"minbound"`**: exact minimax minimum-area enclosing ellipse via `ellipsoidhull()`.

`ellipseInConfig()` supports `mid = "centroid"` (default) or `mid = "nullnull"` (forces center at origin). The `angle` in all ellipse output is in **radians**.

### Axial partitions (`axial.R`)
- **`axialLine()`**: binary split. Classical LDA Bayes-rule boundary — perpendicular to LD1 through the midpoint of class means. Requires exactly 2 group levels. Vertical-line guard: when `|w[2]| < 1e-10`, `slope = Inf` and `intercept` carries the x-position. Returns `predicted` (LDA class factor); the only function that does.
- **`axialLines()`**: k ≥ 2 groups, k−1 parallel lines. Joint search over **angle and cuts**: grid of `n_angles` angles in [0, π) plus LDA's LD1 direction; for each angle, exhaustive enumeration of C(n−1, k−1) cut placements. Ties broken by **largest minimum margin** (perpendicular distance from a cut line to the nearest point). Same vertical-line guard as `axialLine()`. The cut search is **vectorised via cumulative per-group counts** (`cum[i+1, g]` = count of group g among the first i sorted points): a segment's group counts are a vector subtraction `cum[hi+1,] - cum[lo+1,]`, and all C(n−1, k−1) candidate partitions are scored together — no per-combo R loop, no per-segment `tabulate()`. Do not "simplify" this back to a nested loop over `combn()` columns.
- Candidates are scored by **`.bij_best()` (`utils.R`)** — the exact bijection-constrained misclassification. Earlier versions accumulated each segment's own **local-majority** count (`pmax` over group counts per segment), which lets two segments claim the same group and therefore minimises a total no bijection can reach; the search then ranked candidates by a different quantity than `misclass`, so the returned lines need not have minimised the returned number (measured: strictly better lines available in 8 of 40 runs at k=4). The reported `misclass` was never itself wrong — it is recomputed downstream from `majority[sector]` — so the symptom was a **suboptimal partition, not a false number**. **Do not revert to per-segment maxima.** Since the margin is now computed only for the co-minimal candidates rather than all `M`, the bijection scan is roughly cost-neutral (measured slightly *faster* at k=4, n=60).
- `combos <- combn(n_pts - 1L, k - 1L)` is built for **all k ≥ 2** (the old code special-cased k=2 with its own closed-form scan); cut positions are strictly increasing, so **every segment is non-empty** and a partition leaving a group's strip empty is never considered. This differs from the radial functions, which do allow empty regions — see below.
- **When to use which**: use `axialLine()` for the classical LDA classifier (optimal under Gaussian equal-covariance classes); use `axialLines()` for the empirically best parallel-line separator (can find a non-LD1 direction that beats LDA on the training sample).

### Radial / nested circles (`radial-circle.R`)
- **`radialCircle()`** / **`radialCircles()`**: nested (inclusive) circles. Center optimised by **multi-start Nelder-Mead with `parscale`** set to the data range. Starts include the overall centroid, each group's centroid, and (for `radialCircles()`) the previous circle's center. Nesting constraint `r_s ≥ dist(center_s, center_{s−1}) + r_{s−1}` enforced via minimum radius during a brute-force radius scan (`.best_radius()`). `misclass` is a plain **integer**. Supplying both `cx, cy` to `radialCircles()` makes all circles **concentric**. The inside-to-outside group ordering the sequential fit needs is **searched, not taken from the factor levels** — see "Factor level order must never matter".
- **Every candidate radius is scored by the bijection-constrained misclassification** — the best total correct over all `k!` region-to-group matchings, i.e. exactly what `.assign_groups()` computes downstream — so the search minimises the number the function reports. Earlier versions scored each region by its own *local majority* (`radialCircle()`) or by *fixed factor-level order* (`radialCircles()`), both of which minimise a different, sometimes unreachable quantity; that was a real bug (measured: `misclass` 9 where 4 was reachable at the same centers). **Do not reintroduce per-region local majorities or level-order scoring.** Same bug class as the one fixed in `angular.R` — see the warning there.
- Helper split: `.cut_radii()` enumerates the **realisable** cut positions along the distance-sorted sequence with the radius and margin realising each; `.radial_search()` does the joint search; `.nested_sector()` and `.partition_err()` map radii → regions → bijection-constrained error; `.refine_radii()` is the coordinate-descent pass. `.radial_cuts_2()` no longer exists.
- **Realisability matters.** A cut position `p` is only reachable if some radius yields exactly `p` points with `dist <= r`: `p = 0` needs `s_dist[1] > 0`, an interior `p` needs `s_dist[p] < s_dist[p+1]` (**no radius separates coincident distances**), `p = n` always works. Scoring an unrealisable split reports an error the returned geometry does not achieve — the previous code did this on tied distances. `.best_radius()` likewise **clamps to `r_min`** rather than skipping candidate midpoints below it; testing `r_cands[i] >= r_min` drops splits still reachable at `r = r_min` (hit ~20% of calls in the independent-centers branch).
- **Degenerate partitions (an empty region) are allowed**, because on data with no radial structure they really are the minimum of the stated criterion — but the margin tie-break prefers a partition whose every circle actually splits points, so they only win when strictly better. This is why `radialCircle()` and `radialCircles(k = 2)` now return the **same** circle at the same center; they used to disagree (each suboptimal in a different way) because only `.best_radius()` considered them.
- **Optimality by branch.** Concentric: all `k-1` radii searched *jointly* over every realisable combination (combinations with repetition, `choose(m + k - 2, k - 1)` candidates, vectorised over the candidate axis with the same two-stage bound-and-prune as `.angular_search()`) — globally optimal for that center. Past a cap of `3e7` index cells it **warns** and falls back to the sequential path (`k = 6`, `n = 60` already falls back; `k = 7`, `n = 60` would otherwise need a 6 × 90.8M matrix). Optimised centers: sequential fit, then `.refine_radii()` coordinate-descends every radius against the reported criterion — optimal in each individual radius, not jointly in the centers. The centers themselves still come from the sequential `.best_radius()` proxy, so `radialCircle()` and `radialCircles(k = 2)` can still pick different *centers*.
- `optim()` does very little here: the objective is a piecewise-constant integer, so `reltol` reports convergence after the initial simplex — **3 function evaluations, returning the start point unchanged**. The multi-start center search is in practice *best-of-the-starts*. Don't be surprised by the low evaluation counts, and don't assume tightening `reltol` helps.

### Radial / nested ellipses (`radial-ellipse.R`)
- **`radialEllipse()`** / **`radialEllipses()`**: elliptic analogue of the radial circle functions. Each ellipse has 5 parameters `(cx, cy, a, b, angle)` optimised by Nelder-Mead with `parscale = c(x_range, y_range, max_range, max_range, pi)`. Multi-start includes the covariance ellipse of the inner groups plus an inflated copy of the previous ellipse. `misclass` is a **list `(n, indices)`** — count plus row indices. Angles are in radians internally; converted to degrees only for `draw.ellipse()`. When `ellipse` (a 5-vector) is supplied to `radialEllipses()`, outer ellipses are uniform scalings sharing the fixed center/orientation/ratio; scale factors found by exact 1D scan via `.best_radius()`.
- **`misclass` type differs from circle functions**: `radialEllipse()` / `radialEllipses()` return `misclass` as a list `list(n, indices)`; `radialCircle()` / `radialCircles()` return `misclass` as a plain integer.

### Guttman monotonicity coefficient (`guttman.R`)
- **`mu2()`**: Guttman's mu2 for two vectors. Computed as `sum(dx * dy) / sum(|dx| * |dy|)` over all pairs (i, j), where `dx = x_i - x_j`. Returns values in [−1, 1]; `NaN` when all differences are zero. Uses pairwise NA deletion.
- **`mu2df()`**: Applies `mu2()` to all column pairs of a data frame. Returns a full symmetric matrix (`as_dist = FALSE`, default) or a `dist` object of `sqrt(1 − mu2)` values (`as_dist = TRUE`). Unlike the partition functions, these have no plot side-effect.

### Angular partition (`angular.R`)
- **`angularPartition()`**: k wedge sectors from a common center. Brute-force over `M = choose(n, k)` candidate cut-gap k-tuples (`combn(n, k)`); tie-broken by **largest minimum 2D distance** from any cut ray to the nearest point. The score of a candidate is the exact **bijection-constrained** misclassification (best total correct over all `k!` arc-to-group assignments, each group used exactly once — the same criterion `.assign_groups()` applies downstream). `.angular_search()` computes every per-candidate quantity as a length-`M` vector indexed out of the cumulative count table, so loops run over `k`/`k!`, never over candidates — the same vectorisation pattern as `axialLines()` (loop the small fixed dimension, vectorise the candidate axis).

  Scoring is **bound-and-prune** in two stages, because the `k!` scan is the expensive part:
  1. *All M, cheap*: `ub`, the **unconstrained** best-correct — each arc independently keeps its local-majority group. Any bijection is one particular per-arc group choice, so `exact <= ub` always, making it a valid upper bound. Costs `k * (2k - 1)` vector ops vs `k! * (k + 1)` for the exact scan, and needs no `M x k` matrix.
  2. *Tiny subset, exact*: only candidates whose `ub` is high enough to still win get the full `k!` scan; the threshold walks down until some candidate's exact score reaches it, at which point every unscanned candidate has `ub < best` and is provably excluded.

  The bound is tight in practice (typically a *handful* of the `M` candidates survive — e.g. 8 of 487,635 at n=60/k=4), which is what makes this fast. The margin tie-break is likewise computed **only for the co-minimal candidates**, not all `M`. Degenerate inputs (all one group, alternating labels) loosen the bound but do not blow up — worst case degrades toward the full scan.

  **Do not "simplify" this back to scoring all `M` candidates exactly, and do not drop the bijection constraint in favour of per-arc local majorities** — the latter was a real bug (search minimised a different quantity than the reported `misclass`; see git history), the former was a ~3x slowdown. Any change here must be checked for *bit-identical* `misclass`/`margin`/`cuts`/`center`/`sector`/`majority` against the previous implementation, not just equal `misclass`.

  Center is **optimised** when either `cx` or `cy` is `NULL` (default); starts are the overall centroid, the bounding-box corners, plus each group's centroid. Ray length is computed from `par("usr")`. When `fill = TRUE`, each of the `k` wedges is shaded as a `polygon()` pie slice (center plus a 100-point arc at that ray length); relies on default plot-region clipping rather than the rectangle-clipping used elsewhere, since a pie slice is already bounded. `angularPartition3()` (fixed k=3 reference) exists only in the companion script layer and is not part of this package.
- All exported drawing functions accept `add = TRUE` (default, draw on the existing plot) or `add = FALSE` (call `plot()` first). `ellipseInConfig()` labels no points when `add = FALSE`; all other functions also draw group labels via `graphics::text()`.

#### `angularPartition()` runtime

Measured runtime and candidate-count tables across n and k, with the caveats that explain their ~10x variance, live in the `facpart-angular-perf` skill (`.claude/skills/facpart-angular-perf/SKILL.md`) — consult it before worrying about angular performance or after changing the search code. Headline: `k <= 4` is effectively free up to n=50; `k = 5` is the inflection point; supplying `cx`/`cy` is the single biggest lever.

## Coding Conventions

- Use `_` not `.` for object names (e.g., `grp_int`, not `grp.int`).
- Indentation: 4 spaces.
- Do not use ggplot2 for plots; all graphics use base R.
- Never use function names as object names (e.g., avoid `levels <- levels(x)`).
- Private helpers are prefixed with `.` and tagged `#' @noRd`.
- Do not add top-level `require()` calls — package imports handle dependencies.
- Every exported function returns `invisible(NULL)` when `output = FALSE`; this is a package-wide convention.
- `ellipseInConfig()` has a `labs` parameter that is currently unused but kept for backward compatibility — do not remove it.

- The previously documented roxygen2 `@noRd must not be followed by any text` WARNING for `angular.R` no longer reproduces: with roxygen2 8.0.0 / R 4.6.1, `devtools::document()` runs clean and leaves `man/` and `NAMESPACE` unchanged (i.e. generated docs are currently in sync with the sources).
